# NELoRa 재검증 — 보고된 신경망 이득은 어디로 갔는가

> *NELoRa 원본 캡처에서 검출기 세 종을 같은 심볼에 비교했다. "하드웨어 파형 부정합"
> 으로 보였던 몫은 데이터셋 전역의 **상수 동기 오프셋 하나**였고, 보정하면 사라진다.
> 남는 것은 검출기 격차이며, 그 크기가 논문이 신경망으로 보고한 이득보다 크다.*
>
> 측정일 2026-09-21 · 대상 [10] NELoRa (SenSys'21) · 본편 README §7.3 의 후속
>
> ⚠️ 이 문서의 SNR 축은 **합성 AWGN** 이다. 받은 릴리스에 SNR 라벨이 없어 캡처에
> 잡음을 더해 만들었고, 캡처 자체가 이미 잡음을 포함하므로 실제 SNR 은 표기값보다
> 약간 낮다. 절대 dB 가 아니라 **같은 축 위에서의 검출기 간 격차**만 읽어야 한다.
>
> ⚠️ 신뢰구간을 붙이지 않았다. 부분표본을 바꾸면 10% SER 교차점이 **±0.2~0.3 dB**
> 움직인다(아래 SF7 두 실행 비교). 본편 README 의 부트스트랩 관행을 아직 적용하지
> 않았으므로, 소수점 둘째 자리는 신뢰하지 말 것.

---

## 0. 요약

| 주장 | 결과 |
|---|---|
| D2→D3 = "이상적 chirp 가정과 실제 하드웨어 파형의 부정합" | **기각.** 보정 후 +2.59 → **+0.07 dB** |
| 0.83 이라는 낮은 파형 상관 | 하드웨어 왜곡 아님. **상수 오프셋** τ=+2.00 샘플, ε=+0.188 bin → 상관 0.989 |
| 5.8% SER 바닥 | 잡음도 라벨 오염도 아님. **±1 bin 동기 오차**, 패킷 단위로 집중 |
| 남는 실제 격차 | **D1→D2 = +3.5 ~ +4.3 dB** (SF7~10), 논문의 신경망 이득 1.84~2.35 dB 보다 크다 |

핵심은 격차를 새로 찾은 것이 아니라 **귀속이 잘못돼 있었다**는 것이다. 신경망에
넘길 몫으로 보였던 부분이 고전적 정렬로 회수된다.

## 1. 데이터셋 — 받은 것은 SNR 릴리스가 아니다

`verification/nelora_mf_test.py` 는 NELoRa 의 **SNR별 릴리스**
(`{code_est}_{snr}_{sf}_{bw}_{batch}_{code_label}_{packet}_{symbol}`) 를 전제로 쓰여 있었으나,
손에 있는 것은 **생캡처 릴리스**였다.

| 항목 | 실제 |
|---|---|
| 파일 형식 | MAT 컨테이너 아님. **헤더 없는 interleaved float32 (complex64)** |
| 경로 | `<SF>/<packet>/{symbol_idx}_{code_label}_{packet_id}_{sf}.mat` |
| 4번째 필드 | **패킷 ID** (184개 값 × 각 78회, 디렉터리명과 중복 — 새 정보 없음) |
| 크기 | SF7 8192 B = 1024 샘플 = OSF 8 × 128. SF8/9/10 도 동일 비율 |
| 표본화 | fs = 1 MHz, BW = 125 kHz, **OSF = 8** (전 SF 공통) |
| SNR 필드 | **없음** |
| 빠진 심볼 | `symbol_idx` **10, 11** — SFD 다운چ프 자리 (§5 에서 결정적) |

`code_label` 이 재래식 디코더 출력일 가능성(그렇다면 D1 이 자기가 만든 정답을 맞히는
셈이 되어 비교가 기울어진다)을 따로 검증했고, **기각**했다:

- preamble(`symbol_idx` 0~7)의 `code_label` 이 **99.8%** 가 0 — 프로토콜 구조와 일치
- D1 과 D2 의 예측이 갈린 22개 심볼에서 라벨이 D1 쪽 50.0%, D2 쪽 4.5%, **둘 다 아님 45.5%**
  — 라벨이 D1 계열 생성기의 출력이라면 나올 수 없는 분포

## 2. 방법

검출기 세 종을 **같은 심볼**에 건다.

| | 정의 |
|---|---|
| **D1** | NELoRa baseline. dechirp → FFT → `abs(cut1) + abs(cut2)` → argmax (원본 `chirp_abs_alias` 와 동일) |
| **D2** | 이상적 MF. 해석적으로 생성한 chirp 프로토타입 뱅크와의 비동기 상관 |
| **D3** | 경험적 MF. 실제 캡처에서 추정한 코드별 파형 프로토타입(주성분)과의 상관 |

설계상 지킨 두 가지:

1. **SNR 축은 합성.** NELoRa 자신이 데이터셋을 만드는 방식(캡처 + AWGN)을 따랐다.
2. **프로토타입 패킷과 평가 패킷을 완전히 분리.** 같은 캡처로 프로토타입을 만들고
   그 캡처를 평가하면 D3 이 자기 잡음 실현을 알아보게 되어, 없는 D2→D3 격차가
   생긴다. 패킷 단위로 갈라 이 누수를 원천 차단했다.

## 3. 5.8% SER 바닥의 정체

무잡음 원본 캡처, 평가 6000심볼 (`verification/nelora_floor.py`).

**세 검출기는 서로 동의하는데 라벨과만 어긋난다.**

| | 심볼 수 | 비율 |
|---|---|---|
| 하나라도 틀림 | 369 | 6.15% |
| **셋 다 틀림** | **355** | **5.92%** (틀린 심볼의 96.2%) |
| 셋 다 틀리고 **세 예측까지 일치** | 345 | 셋 다 틀린 것의 **97.2%** |

**오류 형태는 사실상 전부 ±1 bin이다.**

| 검출기 | \|예측−라벨\| ≤ 1 인 비율 | 중앙 \|차이\| |
|---|---|---|
| D1 | **99.7%** | 1 bin |
| D2 | 94.6% | 1 bin |
| D3 | 94.5% | 1 bin |

D1 의 오프셋 분포는 `0: 5643, −1: 356, +27: 1` — **−1 쪽으로만 치우친다. +1 은 없다.**
잡음이 원인이라면 대칭이어야 한다.

**패킷 단위로 집중된다.**

- 오류 최다 상위 10% 패킷(12개)이 전체 오류의 **57.5%**
- 최악 패킷 147: 58심볼 중 49개 오류 (84.5%)
- 패킷 내부 오프셋 동질성(최빈값 점유율) 평균 **95.3%** — 패킷은 통째로 밀리거나 안 밀린다

SNR 의존성은 있으나 바닥을 설명하지 못한다 (추정 SNR 5분위별 공통오류율 9.2% → 8.7%
→ 5.2% → 3.2% → **3.4%**). 최상위 분위에서도 3.4% 가 남는다.

> **결론: 데이터 문제도 검출기 문제도 아니고 동기 문제다.**

## 4. 상관 탐색 — D2→D3 의 해석이 뒤집힌다

경험적 프로토타입과 이상적 chirp 의 \|상관\| 이 0.83 인 것이 "하드웨어 왜곡"인지,
단순한 동기 오차인지를 (타이밍 τ, CFO ε) 2D 탐색으로 가른다
(`verification/nelora_sync.py`). ε 축은 DFT 이므로 zero-padded FFT 한 번으로 훑는다.

| 보정 | \|상관\| 평균 | 중앙값 |
|---|---|---|
| 없음 | 0.8324 | 0.8166 |
| 타이밍만 | 0.9360 | 0.9331 |
| CFO만 | 0.9148 | 0.9096 |
| **타이밍 + CFO** | **0.9891** | 0.9891 |

결정적인 것은 값이 아니라 **최적점이 하나로 모인다**는 사실이다:

- **τ = +2.00 샘플, ε = +0.188 bin**
- 128개 코드 중 **121개**가 같은 τ, IQR 이 `+2.00~+2.00` / `+0.188~+0.188` — 폭이 0
- **SF7/8/9/10 네 SF 모두 동일한 값** (§7)

코드마다 제각각이면 하드웨어 왜곡이지만, 하나의 상수면 캡처·추출 체인의 고정 오프셋이다.

## 5. 동일 보상을 걸고 다시 측정

세 검출기에 **같은** 보상을 건다 (`verification/nelora_cfo.py`, 평가 4000심볼).
10% SER 도달 SNR (합성 AWGN 기준):

| 보상 | D1 | D2 | D3 | D1→D2 | **D2→D3** | D1→D3 |
|---|---|---|---|---|---|---|
| C0 보정 없음 | −14.22 | −16.04 | −18.63 | +1.82 | **+2.59** | +4.40 |
| **C1 전역 상수 정렬** | −14.23 | **−18.56** | −18.63 | **+4.33** | **+0.07** | +4.40 |

> **D2→D3 이 +2.59 → +0.07 dB 로 붕괴한다. 하드웨어 파형 몫은 존재하지 않는다.**

전역 상수는 **프로토타입 패킷에서만** 추정해 평가 패킷에 적용했다(누수 없음).

### C2 가 실패한 이유 — 이것도 결과다

실제 수신기처럼 **패킷별 preamble** 로 (τ, ε) 를 추정하는 팔(C2)은 실패했고,
이유가 그 자체로 데이터셋의 성질을 드러낸다 (`verification/nelora_cfo2.py`).

선형 chirp 은 **delay-Doppler 결합** 때문에 τ 이동과 ε 이동이 거의 같은 효과를 낸다.
preamble 은 전부 code 0 (같은 chirp)이므로 2D 지표가 **능선(ridge)** 이 되어 두 축이
분리되지 않는다:

- 최대값의 99% 이상인 (τ, ε) 점이 **65 / 2145 개**
- 능선 기울기 **+0.1250 bin/샘플 = 정확히 1/OSF** (이론값과 일치)

실제 LoRa 수신기는 SFD **다운چ프**로 이 축퇴를 깬다. 그런데 이 데이터셋은
`symbol_idx` **10, 11 을 아예 빼놨다**. 128개 코드를 쓰는 C1 은 코드마다 순환이동이
달라 축퇴가 깨지므로 잘 동작한다.

τ 를 전역값으로 고정하고 패킷별 ε 만 추정한 C3 도 시도했으나, 184개 패킷 전부
ε = +0.188 로 동일하게 나와 **C1 과 완전히 같은 결과**였다. 패킷별 CFO 변동은
1/16 bin 미만이다.

### 통째로 밀린 패킷 — CFO 가 아니라 추출 정렬 버그

C1/C3 어느 쪽으로도 안 고쳐지는 패킷이 있다. 프로토타입 뱅크를 정수 bin 만큼
밀어가며 오류율을 보면 (`verification/nelora_fair.py`, 1 bin = OSF = 8 샘플):

| 패킷 | −1 bin | **+0 bin** | **+1 bin** | +2 bin |
|---|---|---|---|---|
| 147 | 100.0% | 83.8% | **16.2%** | 100.0% |
| 84 | 100.0% | 79.4% | **20.6%** | 100.0% |
| 177 | 100.0% | 57.4% | **42.6%** | 100.0% |

**심볼 추출 창이 정수 bin 만큼 밀려 잘린 것**이다. 124개 중 3개 = **2.4%**.
CFO 보상으로 고칠 수 있는 종류가 아니며, 데이터셋 정렬 결함이다.

## 6. D1 이 억울하게 불리한 것은 아닌가

"NELoRa 의 검출기가 4 dB 를 잃는다"를 쓰려면, 그 격차가 내가 고른 구현 때문이
아니어야 한다. 이론상 LoRa 의 dechirp+FFT 는 **fs = BW 로 제대로 내리면** 정합필터와
동치이므로, 변형 다섯 가지를 모두 돌렸다 (10% SER, SF7, C1 정렬 적용):

| D1 변형 | 10% SER | 비고 |
|---|---|---|
| abs-alias (NELoRa 원본) | −14.23 dB | |
| 브릭월 데시메이션 | −14.20 dB | 원본과 **−0.04 dB** 차이 |
| 동기(복소합) 결합 | **−14.95 dB** | D1 계열 최고 |
| OSF=1 데시메이션 (위상 0) | −7.77 dB | 안티앨리어싱 없이 내려 잡음이 8배 접힘 |
| OSF=1 (전위상 비동기합) | −13.56 dB | |
| **D2 정합필터 (정렬됨)** | **−18.56 dB** | |

> **최선의 D1 변형(−14.95 dB)도 D2 와 3.6 dB 차이가 끝까지 남는다.**
> 구현 선택의 손실이 아니라 **비동기 alias 결합 자체의 손실**이다.

⚠️ FFT 업샘플 `U = 2, 4` 변형도 돌렸으나(−7.87 / −11.66 dB), 폴딩 인덱스 매핑이
깨져 나온 값이라 **증거로 쓰지 않았다**. 위 표에서 제외했다.

## 7. SF8/9/10 — 결론이 SF 를 올려도 유지되는가

`verification/nelora_allsf.py`. 정렬 추정을 프로토타입 경유가 아니라 **라벨이 붙은
심볼에서 직접** 하도록 바꿨다 — 고SF 는 코드당 캡처가 부족해 프로토타입이 성립하지
않기 때문이다.

**전역 오프셋이 네 SF 모두에서 동일하다.**

| SF | τ (샘플) | ε (bin) | \|상관\| 정렬 전 → 후 | 코드 커버리지 |
|---|---|---|---|---|
| 7 | **+2.00** | **+0.188** | 0.833 → **0.989** | 100% (코드당 중앙값 29개) |
| 8 | **+2.00** | **+0.188** | 0.835 → **0.994** | 21% (중앙값 0개) |
| 9 | **+2.00** | **+0.188** | 0.853 → **0.996** | 11% (중앙값 0개) |
| 10 | **+2.00** | **+0.188** | 0.620 → 0.579 | 9% (중앙값 0개) |

SF10 의 0.620 → 0.579 는 **읽지 말 것** — 코드당 프로토타입이 1개 수준이라 의미가 없다.

**10% SER 도달 SNR 과 검출기 격차:**

| SF | 보상 | D1 | D2 | D3 | D1→D2 | D2→D3 |
|---|---|---|---|---|---|---|
| 7 | C0 | −14.41 | −16.47 | −18.85 | +2.06 | +2.38 |
| 7 | **C1** | −14.46 | −18.76 | −18.85 | **+4.30** | **+0.10** |
| 8 | C0 | −18.56 | −20.53 | — | +1.97 | — |
| 8 | **C1** | −18.63 | −22.31 | — | **+3.68** | — |
| 9 | C0 | −21.12 | −23.04 | — | +1.91 | — |
| 9 | **C1** | −21.30 | −24.93 | — | **+3.63** | — |
| 10 | C0 | −24.03 | −25.97 | — | +1.94 | — |
| 10 | **C1** | −24.10 | −27.61 | — | **+3.51** | — |

> **정렬된 고전 정합필터가 NELoRa 자신의 baseline 을 3.5~4.3 dB 앞선다.**
> 논문이 신경망으로 보고한 **1.84~2.35 dB** 보다 크다.

SF7 이 두 번 나오는 이유: §5 는 n=4000, §7 은 n=2500 이다. 같은 양 D1→D2 가
+4.33 / +4.30 으로 **0.03 dB**, D2 절대값이 −18.56 / −18.76 으로 **0.2 dB** 움직인다.
이 정도가 현재 표본 흔들림의 크기다.

### 함정 하나 — "교차 없음" 은 바닥이 높다는 뜻이 아니었다

처음 고정 SNR 격자(0 ~ −20 dB)로 돌렸을 때 SF8/9/10 이 "교차 없음"으로 나왔는데,
바닥이 높아서가 아니라 **격자가 얕아서**였다. 고SF 는 처리이득이 커서 −20 dB 에서도
10% 에 못 미친다. 무잡음 원본 오류율을 직접 찍어 확인했다:

| SF | 무잡음 D1 | 무잡음 D2 | 통째로 밀린 패킷 |
|---|---|---|---|
| 7 | 3.83% | 4.05% | 0 / 61 |
| 8 | **0.00%** | **0.00%** | 0 / 19 |
| 9 | **0.00%** | **0.00%** | 0 / 21 |
| 10 | 4.17% | 4.17% | 1 / 24 (pkt 3, +1 bin) |

SF 마다 격자를 3 dB 씩 내려 다시 잡았다.

## 8. 한계

1. **SNR 축이 합성이다.** 캡처가 이미 잡음을 포함하므로 실제 SNR 은 표기값보다 낮다.
   절대 dB 를 인용하지 말고 격차만 쓸 것.
2. **신뢰구간이 없다.** 표본을 바꾸면 교차점이 ±0.2~0.3 dB 움직인다. 본편 README 의
   패킷 단위 부트스트랩을 아직 적용하지 않았다.
3. **D3 은 SF7 에서만 성립한다.** N = 2^SF 는 커지는데 캡처 수는 그대로여서 SF8/9/10
   코드 커버리지가 21% / 11% / 9% (코드당 중앙값 0개)다. 표에서 `—` 로 비워 뒀다.
4. **NELoRa 의 DNN 경로 자체는 돌리지 않았다.** 비교 대상은 논문이 보고한 dB 수치이지
   재현한 신경망이 아니다. 신경망까지 같은 정렬 조건에서 돌려야 비교가 완결된다.
5. 이 릴리스에 **SFD 가 없어** 실제 수신기의 동기 경로를 그대로 재현할 수 없었다.

## 재현

```bash
cd verification

# 0. 구조 확인 (SNR 릴리스가 아님을 확인)
python nelora_mf_test.py inspect ../NeLoRa_Dataset/7

# 1. 세 검출기 비교 (생캡처 모드)
python nelora_mf_test.py raw ../NeLoRa_Dataset/7 --sf 7 --per-snr 4000

# 2. 5.8% 바닥의 정체
python nelora_floor.py ../NeLoRa_Dataset/7 --sf 7 --n 6000

# 3. 상관 탐색 — D2->D3 이 동기인가 하드웨어인가
python nelora_sync.py ../NeLoRa_Dataset/7 --sf 7

# 4. 동일 보상 후 재측정 (C0 / C1 / C2)
python nelora_cfo.py ../NeLoRa_Dataset/7 --sf 7 --n 4000

# 5. 축퇴 확인 + C3 + D1 공정성
python nelora_cfo2.py ../NeLoRa_Dataset/7 --sf 7

# 6. 밀린 패킷의 정체 + D1 변형 비교
python nelora_fair.py ../NeLoRa_Dataset/7 --sf 7

# 7. SF7/8/9/10 전체
python nelora_allsf.py ../NeLoRa_Dataset --sfs 7,8,9,10 --n 2500
```

`NeLoRa_Dataset/` 는 용량 때문에 `.gitignore` 에 있다. 원본 릴리스를 따로 받아
저장소 루트에 `NeLoRa_Dataset/{7,8,9,10}/<packet>/*.mat` 구조로 두면 된다.

### 파일 구성

| 파일 | 역할 |

| `nelora_cfo.py` | 보상 수준 C0/C1/C2 비교 |
| `nelora_cfo2.py` | delay-Doppler 축퇴 확인, C3, D1 변형 |
| `nelora_fair.py` | 밀린 패킷 진단, 데시메이션판 D1 |
| `nelora_allsf.py` | SF7/8/9/10 일괄 |

## 본편 README 와의 관계

§7.3 은 NELoRa 의 1.84~2.35 dB 를 "설명해야 할 기정사실"로 두고, 그 원인이
denoising 이 아니라 임페어먼트 보상일 것이라는 가설을 세웠다. 이 재검증은 §7.3 이
열어두지 않았던 세 번째 갈래에 무게를 싣는다 — **보고된 이득이 고전적 정렬로 회수되는
몫과 같은 크기이거나 그보다 작다.**

§4.2 의 AWGN 심볼 단위 정리는 이 결과에 의존하지 않으므로 그대로 유효하다.

이것은 출판된 철회가 아니라 한 데이터셋 릴리스에서의 측정이다. 어떤 글에서도
**열린 질문**으로 쓰고, 단정이나 비난으로 쓰지 말 것.
